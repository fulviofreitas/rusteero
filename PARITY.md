# PARITY — rusteero vs eero-api

Per-method checklist against `fulviofreitas/eero-api` at tag `v8.4.1` (commit `c0e76cf`, 2026-10-20). Completion criterion: every row is **ported**, **dropped** (with reason), or **changed** (with reason), and every ported row has a wiremock test pinning verb, path and body.

Status values: `ported` (with test) · `changed` · `renamed` · `identical` · `dropped`.

**What changed since the previous baseline (v8.0.4).** This baseline ports v8.0.5 through v8.4.1. The default `User-Agent` is now the current iOS client string `eero-ios/2026.8.1 (iPhone; iOS 18.5)`; the old value is `consts::LEGACY_USER_AGENT` and either builder's `.user_agent()` sets one. Version pins are applied after URL resolution through `links::rewrite_version`, so a published link or caller path on another version cannot move them: `get_support`, `get_forwards` and `get_routing` are pinned to 2.2, the device writes (`set_device_nickname`, `pause_device`) and the four WAN methods to 2.3. `set_dhcp` accepts the `custom` mode and sends `manual` as `custom`. The nine time-windowed data-usage reads take a per-call `timeout: Option<RequestTimeout>` (a breaking signature change) that replaces the transport default wholesale for that request. Transport log lines above `DEBUG` no longer carry a URL or reqwest's message, and `redact_sensitive` walks top-level arrays and stops at a depth of 16. An undecodable or non-object 2xx body is a typed `Error::Api`. `Error::Authentication` and `Error::RateLimit` gain `status: Option<u16>` (breaking fields), and a parsed `Retry-After` is capped at one day (`consts::RETRY_AFTER_MAX`). The credential gate compares the full origin (scheme, host, effective port, no userinfo) through `links::origin_mismatch`, `base_url` is validated at build time, and a caller path or URL must stay inside the resource family of the call (`links::require_family_path`). Login keeps the stored session until verify succeeds. The shipped credential stores read every save back (`StorageError::NotRetained`), `credentials_persisted()` reports the outcome, each file and keyring store serialises its own operations, and the session setters are `async` (breaking). The client cache refuses a fill that an invalidation overtook (a generation guard), keys devices by canonical MAC, and a session change forgets an auto-discovered network. The Wi-Fi password and name setters reject an empty value before any request. New methods: `AccountApi::get_account` (`NetworksApi::get_account` is deprecated), `set_hide_5g`, `set_preferred_update_hour`, `set_ipv6_upstream`, `get_eeros_usage` and the network ad-block and malware switches, plus the 8.4.0 `Client` facade wrappers (`reboot_network`, `request_support`, `add_to_blacklist`, `remove_from_blacklist`, `create_burst_reporter`, the two bedtime helpers, `set_ipv6_upstream`, `get_eeros_data_usage`, `set_network_ad_block`, `set_network_block_malware`, `clear_auth_data`). `add_to_blacklist` (and `block_device` through it) and the default `create_burst_reporter` body are live-verified upstream, so their uncharacterised-write warnings are gone; `reporter_data` is optional and deprecated (a breaking signature change). Upstream changes with no Rust counterpart are listed under [Upstream changes not ported](#upstream-changes-not-ported). The earlier move from the `e7bcfd9` baseline (effectively v6.2.0) to v8.0.4 is described in `CHANGELOG.md` (2.0.0) and on the wiki Migration page (1.0.0 → 2.0.0).

**Trailing slash on published self urls.** Every `DataUsageApi` method and the two network-level `DnsPoliciesApi` switches (`set_network_ad_block`, `set_network_block_malware`) join their suffix to a parent's published url without doubling a trailing `/`; Python sends `…//data_usage` there. The divergence is deliberate and pinned by the trailing-slash tests in `tests/endpoints_data_usage.rs` and `tests/endpoints_dns_policies.rs`.

Path column legend: `**2.2**` / `**2.3**` marks an endpoint pinned to that API version: the URL is resolved first and then rewritten with `links::rewrite_version`, so a published link or a caller path naming another version is pinned too; `link:<name>` after a path means the route prefers the parent's published `data.resources.<name>` link when a `parent` is supplied; `link:self` means it prefers the parent's own `data.url`. Bodies in parentheses: `(form …)` is `application/x-www-form-urlencoded`, `("")` is the two-character JSON-string body, otherwise JSON.

**Summary:** 299 rows (287 in the method table, 12 in the credential-storage table) — changed: 30, dropped: 20, identical: 2, ported: 243, renamed: 4. **No row is `planned`.** Every row is ported, changed with a reason, dropped with a reason, identical or renamed. 14 of the 20 `dropped` rows are v8.0.0 upstream removals (methods that no longer exist upstream, listed for readers of the older baselines); the other six are `EeroAPI.__aenter__/__aexit__`, `close()` and re-enterable sessions, `EeroClient.login/verify`, `require_bool`, the Python-logging adapter and the unused `const.py` enums.

## Upstream changes not ported

Changes between v8.0.5 and v8.4.1 that have no Rust counterpart, each with the reason. Changes to upstream's own repository tooling are listed too, so the list covers every release.

### 8.0.5

- `AuthenticatedAPI.__init__` falling back to `DEFAULT_USER_AGENT` when `auth_api` is not a real `BaseAPI`: a workaround for `MagicMock` test doubles; Rust domain modules take a concrete `Arc<Transport>` whose `User-Agent` is validated once at build.
- `EeroClient.set_preferred_network` accepting an `int` and storing `str(id)`: the Rust method takes `impl Into<String>`, so the caller converts an integer (`.to_string()`).
- commitlint `body-max-line-length` disabled: upstream repository tooling for its squash-merge flow, not library behaviour.
- commitlint `footer-max-line-length` raised to 250: upstream repository tooling, not library behaviour.

### 8.1.0

- Re-enterable sessions (`BaseAPI.__aexit__` closes the owned session, and a second `async with` opens a fresh one): there is no closed state; `Drop` releases the reqwest pool, and a new `Client` gets a fresh one.
- An idempotent `async close()` on `BaseAPI`, `AuthAPI`, `EeroAPI` and `EeroClient`: dropping the `Client` does what `close()` does, exactly once, and nothing can use it afterwards.
- `BaseAPI.__aexit__` never swallowing an exception raised in the `async with` body: an artefact of Python's `__aexit__` return-value protocol; Rust has no async context manager, and `Drop` always runs.

### 8.1.1

- `_redact` walking tuples and returning tuples: `serde_json::Value` has no tuple type (arrays are walked).
- `_redact` walking any `collections.abc.Mapping`: `Value` has a single map type, which is walked.
- Sensitive-key matching through `str(key)` for non-string keys: JSON object keys are always strings.
- The `_redact` cycle guard: an owned `Value` cannot hold a reference cycle or a shared node, so only the depth cap applies.
- `SecureLoggerAdapter.log()` as the single redaction path: `tracing` has no logger-adapter layer; values are redacted where they are logged.
- `SecureLoggerAdapter.process` merging the adapter's `extra` with the call's: `tracing` has no adapter-level context; structured fields are given per event.
- `SecureLoggerAdapter.process` redacting a container passed as the message: `tracing` messages are format strings, and containers are logged as fields that are already redacted.
- `SecureLoggerAdapter` `stacklevel` attribution: `tracing` callsite metadata always names the calling module, file and line.

### 8.1.2

- Keyword-only, `None`-defaulting `status_code` / `retry_after` constructor arguments on `EeroAuthenticationException` / `EeroRateLimitException`: enum variants have no keyword or positional constructors, and `Error::authentication()` still builds `status: None`.
- The pinned exception hierarchy (`EeroValidationException` is not an `EeroAPIException`; the auth and rate-limit exceptions are direct children of `EeroException`): there is no class hierarchy, so the observable rules are pinned instead (`Validation` carries no status, `RateLimit` is never an auth error).

### 8.1.3

- The credential gate counting an unparseable authority as a mismatch (`ORIGIN_UNPARSEABLE`, `ORIGIN_BAD_BASE`): the gate judges the already-parsed `Url` that reqwest sends, so an unparseable authority never reaches it.
- `BaseAPI._resolve_url` matching the `http(s)://` prefix case-insensitively: `Transport::request` takes a parsed `Url`, never a string to prefix-match.
- `resource_url` returning an absolute URL with the caller's literal scheme spelling (`HTTPS://…`): `url::Url` lower-cases the scheme on parse; such a URL is still accepted.

### 8.1.4

- `is_authenticated`, `get_auth_token`, `logout` and a terminal refresh acting on the unverified token while a login is pending: a `PendingLogin` is never the active session.

### 8.1.6

- Rejecting non-`str` passwords (`None`, `False`, `0`, bytes, …) in the two password setters: `password` is a `&str`.

### 8.1.7

- `require_bool("enabled")` in `set_guest_network`: `enabled` is a `bool`, so the check can never fail.
- Rejecting non-`str` names in `set_network_name` / `set_guest_network`: `name` is a `&str` / `Option<&str>`.
- The shared `require_bool` helper: a Rust parameter typed `bool` cannot hold anything else.
- Moving every pytest fixture to `tests/conftest.py`: Python test infrastructure for pytest 9; cargo has no order-dependent fixture discovery.

### 8.1.8

- `login()` resetting `credentials_persisted` to `True` when it installs a pending token: a `LoginFlow` never installs its token on the transport, so there is nothing to reset.
- The `Getting account` DEBUG line in `AccountAPI.get_account`, and the `get_networks` fallback DEBUG line it replaced: the Rust endpoints and `Client` do not mirror Python's per-call DEBUG lines.
- The in-flight invalidation test table holding `account.get_account` open: a Python test-spec change; the `/account` fallback here already takes its own cache generation.

### 8.1.9

- `EeroClient.login` forgetting an auto-discovered network, and `EeroClient.verify` resetting session state: the `Client` has no login or verify (see the `login / verify` row).

### 8.1.10

- A store operation cancelled while it waits for the per-instance lock doing no work: here a dropped caller never skips a queued write or clear (see the `_ThreadOffloadStorage` row).
- Creating the operation lock lazily and rebuilding it per event loop: a `std::sync::Mutex` is not bound to an async runtime.
- Retrieving an abandoned worker future's exception so asyncio never logs "Future exception was never retrieved": tokio has no such warning; failures are returned to the caller and handled under its `StorageFailures` policy.

### 8.2.0

- `require_bool("enabled")` in `set_hide_5g`, on the resource and the `Client`: `enabled` is a `bool`.
- `require_hour` rejecting `bool`, `str`, `float` and `None` hours: `hour` is an `i32`, so those cannot be passed.
- Pinning the shared workflow-arsenal actions to a commit SHA in upstream's CI: upstream repository supply-chain housekeeping.
- The same SHA pin on workflows and jobs that exist only in upstream's Python pipeline: upstream repository tooling.
- Removing a dead Codecov upload from upstream's CI test job: upstream repository tooling.
- Removing the duplicated 8.1.8 section from upstream's `CHANGELOG.md`: release-history housekeeping (8.1.8 never reached PyPI; its changes ship in 8.1.9).

### 8.3.0

- Building releases on Python 3.14 and holding Renovate below 3.15: Python packaging and CI only.

### 8.4.0

- README and wiki ecosystem listings (home-assistant-eero, the eeroctl tap, rusteero itself): documentation of projects built on the Python package.
- The "Used By" tables listing tripwire: documentation of third-party consumers of the Python package.
- `EeroClient.resend_verification_code()`: the `Client` holds no login state; resending is `PendingLogin::resend` (see the `resend_verification_code` row).
- The `DOMAIN_CALL_SHAPES` signature-binding test rows for the new facade wrappers: a Python runtime check that the Rust compiler already performs for every `Client`-to-domain call.

### 8.4.1

- The relative order of `create_burst_reporter`'s DEBUG line and its uncharacterised-write WARNING: Rust endpoints emit no per-method DEBUG line, so only the warning's placement exists, and the endpoint tests pin it.
## Live validation (2026-09-14, pre-v8 port)

A read-only sweep against a real account (4 eeros, 135 devices, 10 profiles) with an
`eeroctl`-issued session token, run against the `e7bcfd9`-baseline port. Every path was
additionally re-probed with raw `curl`, and the two agreed in every case, so no route constant was
wrong. The observations below survive the v8.0.4 and v8.4.1 reworks because the paths they
concern are unchanged; the sweep has **not** been re-run against the v8.0.4 or the v8.4.1 port
(`cargo test --test live -- --ignored --exact live_read_only_endpoint_sweep`).

Confirmed by observation, not just by reading Python:

- `get_dns_settings`, `get_security_settings`, `get_sqm_settings` and `get_premium_status` really
  do return the whole network object, byte-identical to `get_network`. Modelling them as aliases
  of one route is correct.
- **`GET /networks` returned an empty list on this account**, so the `/account` fallback is what
  actually resolved the network id. That fallback is load-bearing in the real world, not a
  vestigial branch — worth knowing before anyone "simplifies" it away.
